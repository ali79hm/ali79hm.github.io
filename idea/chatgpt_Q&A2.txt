A:
Yes. The key decision is: **do not make the website itself as one giant comic image.** Build the layout and all résumé text with HTML/CSS, and use images only for the illustrated scenes.

That gives you the comic look while keeping the site responsive, searchable, selectable, accessible, and easy to update.

### What should be image vs HTML vs SVG?

| Part                          | Use                   | Example                                   |
| ----------------------------- | --------------------- | ----------------------------------------- |
| Your comic character / scenes | **WebP/AVIF image**   | You at computer, whiteboard, Tehran scene |
| Text                          | **HTML**              | Name, experience, skills, descriptions    |
| Headings                      | **HTML + comic font** | `EXPERIENCE`, `SKILLS`                    |
| Speech bubbles                | **CSS + HTML text**   | Bubble around `"I build AI systems..."`   |
| Panel borders                 | **CSS**               | Thick black comic borders                 |
| Buttons                       | **HTML/CSS**          | `VIEW DETAILS →`                          |
| Icons                         | **SVG**               | GitHub, LinkedIn, AI, server, database    |
| Halftone texture              | CSS / small SVG / PNG | comic dots                                |
| Arrows and doodles            | SVG                   | hand-drawn arrows                         |
| Timeline                      | CSS                   | vertical line + dots                      |
| Project screenshots           | WebP/PNG              | Jalali calendar screenshot                |
| Background illustrations      | WebP/AVIF             | Tehran skyline                            |
| Logos                         | SVG when available    | GitHub, LinkedIn, KDE                     |

So instead of generating this:

```text
┌─────────────────────────────┐
│ [an entire JPG containing]  │
│                             │
│ EXPERIENCE                  │
│ Technical Lead              │
│ Roshan                      │
│ March 2025 - Present        │
│                             │
└─────────────────────────────┘
```

you build:

```html
<section class="comic-panel experience">
  <img
    src="/images/experience/tech-lead.webp"
    alt=""
  />

  <div class="experience-content">
    <h2>Technical Lead</h2>
    <h3>Roshan</h3>
    <p>March 2025 — Present</p>

    <p>
      Architecting enterprise AI systems,
      LLM infrastructure and RAG platforms.
    </p>

    <a href="/experience/technical-lead">
      View details →
    </a>
  </div>
</section>
```

The picture gives the **comic atmosphere**. The website gives you the **actual content**.

## Speech bubbles

Don't generate speech-bubble text into your illustrations either.

Make a reusable component:

```html
<div class="speech-bubble">
    I turn complex problems into real-world AI systems.
</div>
```

CSS:

```css
.speech-bubble {
  position: relative;

  background: #fffdf6;

  border: 4px solid #111;
  border-radius: 22px;

  padding: 20px;

  font-family: var(--comic-font);
}

.speech-bubble::after {
  content: "";

  position: absolute;

  bottom: -24px;
  left: 40px;

  border-width: 24px 20px 0;
  border-style: solid;

  border-color:
    #111
    transparent
    transparent;
}
```

Then you can change the words whenever you want.

# You don't necessarily need GSAP

For version one, I might actually have Codex use:

```js
IntersectionObserver
```

It is built into the browser.

Conceptually:

```js
const chapters =
    document.querySelectorAll(".experience-chapter");

const image =
    document.querySelector(".experience-image");

const observer = new IntersectionObserver(entries => {

    entries.forEach(entry => {

        if (!entry.isIntersecting) return;

        image.src = entry.target.dataset.image;

    });

}, {
    threshold: 0.5
});

chapters.forEach(chapter => {
    observer.observe(chapter);
});
```

Then:

```html
<div
 class="experience-chapter"
 data-image="/images/experience/lead-01.webp"
>
   <h3>Architecture & Deployment</h3>
   ...
</div>
```

When it enters the screen:

```text
lead-01.webp
```

appears.

Then:

```text
lead-02.webp
```

etc.

You can later add GSAP to make transitions more sophisticated.

# The image can transition like a comic frame

Don't instantly swap it.

For example:

```css
.experience-image {
    transition:
      opacity 0.35s ease,
      transform 0.45s ease;
}
```

When changing:

```text
old image
      ↓
fade
      ↓
slightly zoom
      ↓
new comic panel
```

You could eventually make it look like:

```text
WHAM!
```

or:

```text
NEXT CHAPTER →
```

between major jobs.

But keep the first version simpler.

# For images: don't use JPG by default

For your site I would mostly use:

**WebP**.

For example:

```text
hero.webp
experience-lead-01.webp
experience-lead-02.webp
project-jalali.webp
education.webp
contact.webp
```

WebP is usually dramatically smaller than PNG while still looking very good.

If transparency is needed:

```text
PNG
```

or transparent WebP.

Use JPEG mainly for photographs.

SVG should be used for **simple vector graphics**, not giant comic scenes.

Good SVG candidates:

```text
brain.svg
eye.svg
server.svg
database.svg
github.svg
linkedin.svg
mail.svg
arrow.svg
scribble.svg
starburst.svg
```

Bad SVG candidate:

```text
huge detailed comic illustration.svg
```

That can become enormous and difficult to maintain.

## One important trick: deliberately imperfect borders

Normal CSS:

```css
border: 3px solid black;
```

will look very computer-perfect.

Your comic should feel slightly irregular.

For example:

```css
.comic-panel {
  border: 3px solid #111;

  border-radius:
    3px 7px
    4px 5px;

  box-shadow:
    4px 5px 0 #111;
}
```

Some panels:

```css
transform: rotate(-0.3deg);
```

Others:

```css
transform: rotate(0.4deg);
```

Very small differences.

That gives you a hand-built comic feeling without destroying readability.
